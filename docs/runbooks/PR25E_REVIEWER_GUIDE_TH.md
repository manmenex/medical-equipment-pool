# คู่มือผู้ตรวจสอบรายการออฟไลน์ (Needs review)

**Purpose:** คู่มือสำหรับเจ้าหน้าที่ Pool และผู้ดูแลระบบที่ตัดสินรายการออฟไลน์ที่ระบบไม่บันทึกอัตโนมัติ (PR25E)
**Authority:** สัญญา API และกฎ: `docs/api/sync.md`; การออกแบบ: `docs/design/PR25D_OFFLINE_OPERATION_PLAN.md` (9.6, 9.7, 11, 16.1)
**Update trigger:** หน้าตรวจสอบหรือรหัสผลลัพธ์เปลี่ยน
**Maintainer:** Documentation/Governance Engineer

คู่มือสำหรับผู้ปฏิบัติงานหน้างาน: `docs/runbooks/PR25E_OPERATOR_GUIDE_TH.md`

## 1. หน้า "ตรวจสอบรายการออฟไลน์"

เปิดที่ `/sync-review` (เจ้าหน้าที่ Pool และผู้ดูแลระบบ; Read Only เข้าไม่ได้) ป้าย "รอเจ้าหน้าที่ตรวจสอบ N รายการ" ที่แถบบนนับเฉพาะรายการของผู้ใช้คนนั้น ไม่ใช่ทั้งระบบ

รายการเรียงให้ "ข้อมูลเก่า" (stale) ขึ้นก่อน แล้วตามเวลาที่ส่งถึงเซิร์ฟเวอร์ แต่ละรายการแสดง อุปกรณ์ (BCM) หน่วยงาน ผู้บันทึก เวลาที่เกิดเหตุการณ์ และเครื่องต้นทาง ไม่แสดง Item No / Asset Number

รหัส `FORBIDDEN` (ผู้บันทึกไม่มีสิทธิ์ ณ เวลาที่ส่ง) เห็นและตัดสินได้เฉพาะผู้ดูแลระบบ

## 2. รหัสผลลัพธ์และสิ่งที่ต้องทำ

ก่อนตัดสินทุกครั้ง ตรวจสถานะปัจจุบันของเครื่อง (หน้ารายละเอียดเครื่อง) หรือเปิด "ดูลำดับเหตุการณ์"

| รหัส | ความหมาย | แนวทาง |
|---|---|---|
| `EQUIPMENT_NOT_AVAILABLE` | ตอนส่ง เครื่องไม่พร้อมเบิก (ถูกเบิกไปแล้ว ชำรุด ปลดระวาง) | หากเป็นการเบิกซ้ำ ปิดรายการ ("บันทึกไว้แล้ว" หรือ "บันทึกซ้ำจากการกรอกหลายครั้ง") หากเป็นเพราะลำดับเหตุการณ์สลับกัน ใช้ลำดับเหตุการณ์ + Apply sequence |
| `TRANSACTION_ALREADY_RETURNED`, `RECEIPT_RACE_LOST` | มีการรับคืนรายการเบิกนั้นแล้ว (หรือพร้อมกันจากอีกที่) | โดยมากปิดรายการ "บันทึกไว้แล้ว" หากสภาพเครื่อง (ใช้ได้/ชำรุด) ต่างจากที่บันทึกไว้ ให้จัดการด้วยขั้นตอนปกติของระบบ |
| `DEPENDENCY_MISSING`, `TRANSACTION_NOT_FOUND` | รับคืนที่อ้างรายการเบิกซึ่งเซิร์ฟเวอร์ไม่พบ `DEPENDENCY_MISSING` รอได้ 48 ชม. เผื่อรายการเบิกยังค้างอยู่ในอีกเครื่อง หลังจากนั้นเข้าหน้านี้ | หาว่ารายการเบิกยังค้างอยู่ในเครื่องอื่นหรือไม่ หากใช่ ให้รอให้ส่ง หรือจัดลำดับ เบิกก่อนรับคืน ด้วย Apply sequence หากไม่มีจริง ปิดรายการ "ไม่ใช่รายการจริง" หรือ "ดำเนินการด้วยวิธีอื่นแล้ว" |
| `EQUIPMENT_NOT_FOUND` | ไม่พบเครื่องในระบบ | ตรวจข้อมูลหลัก ปิดรายการเมื่อไม่ใช่รายการจริง |
| `OP_TOO_OLD` | เวลาเกิดเหตุการณ์ (หลังปรับนาฬิกาเครื่อง) **เก่ากว่า 7 วัน** ก่อนที่เซิร์ฟเวอร์รับรายการครั้งแรก ระบบไม่บันทึกและไม่ปรับเวลาให้เอง | ตรวจว่าเหตุการณ์เกิดจริงตามเวลาที่แสดงหรือไม่ "บันทึกทันที" จะใช้ **เวลาเดิมที่แสดง** (ที่ท่านยืนยัน) ไม่ใช่เวลาปัจจุบัน หากไม่จริง ให้ปิดรายการ |
| `FORBIDDEN` | ผู้บันทึกไม่มีสิทธิ์ขณะส่ง | ผู้ดูแลระบบเท่านั้น ตรวจบทบาทผู้บันทึกก่อนตัดสิน |

รหัสอื่น: ระบบแสดงข้อความทั่วไป ให้ดูสถานะเครื่องปัจจุบันแล้วตัดสินแบบเดียวกัน ธง "ข้อมูลเก่า" แปลว่าเครื่องต้นทางไม่ได้ซิงค์เกิน 4 ชั่วโมงตอนบันทึก ควรระวังเป็นพิเศษ

## 3. ปิดรายการ vs บันทึกทันที vs ลำดับเหตุการณ์

| การกระทำ | ผล |
|---|---|
| **ปิดรายการ (dismiss)** | ไม่เปลี่ยนสถานะเครื่อง ไม่มี export event ต้องเลือกเหตุผล (บันทึกไว้แล้ว / บันทึกซ้ำจากการกรอกหลายครั้ง / ไม่ใช่รายการจริง / ดำเนินการด้วยวิธีอื่นแล้ว) หมายเหตุไม่บังคับ มี audit |
| **บันทึกทันที (apply now)** | ส่งรายการเข้า dispatch/receipt service ตามปกติเป็นรายการใหม่ **เวลาทางธุรกิจ = เวลาที่ท่านกดตัดสิน** (ยกเว้น `OP_TOO_OLD` ที่ใช้เวลาเดิมที่ยืนยัน) ผู้บันทึกเดิมยังเป็นผู้บันทึก ท่านเป็นผู้กระทำใน audit หากเงื่อนไขเปลี่ยนไปแล้ว ระบบแจ้งว่าบันทึกไม่ได้และรายการยังอยู่ในรายการรอ |
| **ดูลำดับเหตุการณ์ + Apply sequence** | ใช้เมื่อมีหลายรายการของเครื่องเดียวกันที่ต้องเรียงให้ถูก (เช่น เบิกแล้วรับคืนจากอีกเครื่อง) เลือกรายการและยืนยันลำดับ ระบบเตือน "ลำดับไม่แน่ชัด" เมื่อเวลาซ้อนทับ ระบบบันทึกทีละรายการตามลำดับที่ยืนยัน และ **หยุดที่รายการแรกที่ไม่ผ่าน** รายการที่เหลือยังรอตรวจสอบ รายการที่บันทึกแล้วไม่ถูกย้อน |

**ผลต่อรายงาน (PR16):** รายการที่ตัดสินด้วย "บันทึกทันที" และ Apply sequence นับ `business_date` และ `shift` ตาม **เวลาที่ตัดสิน** ไม่ใช่เวลาที่เกิดเหตุจริง รายการที่ตัดสินข้ามกะหรือข้ามวันจึงไปอยู่ในกะ/วันที่ตัดสิน ควรตัดสินให้เร็ว ระบบไม่ปรับย้อนหลังให้

ไม่มีการตัดสินอัตโนมัติ (Owner decision D8): `SYNC_AUTO_SEQUENCE` ไม่เปิดใช้ ผู้ตรวจสอบเป็นผู้ตัดสินเองทุกรายการ

## 4. สถิติและ CSV (เพื่อการตัดสินใจ D8 หลัง Pilot)

ผู้ดูแลระบบเท่านั้น ในหน้าตรวจสอบมีแผง "สถิติรายการที่ขัดแย้ง (30 วัน)" และปุ่ม "ดาวน์โหลด CSV" (`GET /sync/collisions/stats`, `/sync/collisions/export`; ดู `docs/api/sync.md`) ใช้ดู: จำนวนรายการขัดแย้ง เครื่องที่ขัดแย้งหลายรายการ รายการข้ามอุปกรณ์ และอัตราที่ผู้ตรวจสอบตัดสินตามลำดับเวลาเหมือนที่ระบบจะเรียงอัตโนมัติ ("ตรงกัน") เป็นหลักฐานให้ Owner ตัดสินหลัง Pilot ว่าจะเปิดการเรียงอัตโนมัติหรือไม่ CSV ไม่มีข้อมูลผู้ป่วยและไม่มีเนื้อหาของรายการ

ภาพรวมการทำงานของผู้ดูแลระบบ: `GET /sync/status` และ `GET /sync/stats` (ดู `docs/api/sync.md`) ค่า verify ที่พบรายการไม่รู้จักพุ่งขึ้นหมายถึงอาจมีการกู้คืนฐานข้อมูล

## 5. ข้อควรระวัง

- ห้ามบันทึกซ้ำด้วยมือก่อนตัดสินรายการที่ค้าง จะเกิดรายการซ้ำ
- ผู้ตรวจสอบสองคนกดพร้อมกัน: คนแรกชนะ คนหลังได้ข้อความว่ารายการถูกดำเนินการไปแล้ว
- หลังกู้คืนฐานข้อมูล (`docs/runbooks/PR24_BACKUP_RESTORE_RUNBOOK.md`) เครื่องลูกข่ายจะตรวจและส่งรายการ 48 ชม. ที่ขาดซ้ำ จึงอาจมีรายการเข้าหน้านี้เพิ่ม
