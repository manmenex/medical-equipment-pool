# รายการซ้อมใช้งานออฟไลน์ด้วยมือ (PR25E E1) - สำหรับเจ้าของระบบ

เอกสารนี้เป็นรายการให้ทำจริงบนเครื่องของหน่วยงานก่อนเริ่มนำร่อง
**ยังไม่มีข้อใดผ่านการซ้อมจริง** จนกว่าจะบันทึกหลักฐานในตารางท้ายเอกสาร
การทดสอบอัตโนมัติ (Playwright, `frontend/e2e/`) ใช้ข้อมูลสมมติและฐานข้อมูล SQLite
ชั่วคราว จึงไม่ใช่หลักฐานของเครื่องจริง เครือข่ายจริง หรือ PostgreSQL

ข้อควรระวัง: ใช้เฉพาะอุปกรณ์/บัญชีทดสอบ ห้ามใช้ข้อมูลผู้ป่วย ห้ามจดรหัสผ่านลงในหลักฐาน

## 0. เตรียมการ
- [ ] ระบบติดตั้งบนเครื่องของหน่วยงานแล้ว และเข้าได้จากโทรศัพท์ แท็บเล็ต และคอมพิวเตอร์
- [ ] มีอุปกรณ์ทดสอบ 2 ชิ้น (ระบุรหัส) และบัญชีเจ้าหน้าที่ทดสอบ 2 บัญชี (A, B)
- [ ] ติดตั้งเว็บแอปบนอุปกรณ์แต่ละเครื่องและเปิดออนไลน์หนึ่งครั้งก่อน
- [ ] จดเวอร์ชันแอปและเวลาเริ่ม

## 1. ถอดสายเครือข่ายจริง (โทรศัพท์ / แท็บเล็ต / คอมพิวเตอร์ อย่างละ 1 รอบ)
1. เข้าสู่ระบบขณะออนไลน์ เปิดหน้าจ่ายอุปกรณ์
2. ถอดสาย LAN / ปิด Wi-Fi / เปิดโหมดเครื่องบิน
3. บันทึกการจ่ายอุปกรณ์ทดสอบด้วย BCM Code
4. ปิดแท็บแล้วเปิดใหม่ (ยังออฟไลน์) ตรวจว่ารายการยังอยู่ในคิว
5. ต่อเครือข่ายกลับ รอซิงก์ ตรวจว่าสถานะเป็น "ใช้แล้ว/applied" และมีเหตุการณ์ส่งออกเพียง 1 รายการ
6. ทำซ้ำด้วยจ่ายแล้วรับคืนขณะออฟไลน์ ตรวจลำดับ
7. ทำซ้ำโดยตัดเครือข่ายกลางคันขณะกำลังซิงก์ ตรวจว่าไม่เกิดรายการซ้ำ
- ผ่านเมื่อ: ไม่มีรายการหาย ไม่มีรายการซ้ำ ลำดับถูกต้อง

## 2. คำเตือนข้อมูลค้างเกิน 4 ชั่วโมง
1. ปล่อยอุปกรณ์ออฟไลน์เกิน 4 ชั่วโมง (หรือตามวิธีที่คู่มือผู้ใช้ระบุ)
2. ตรวจว่ามีคำเตือนให้กดรับทราบ และยังแสดงเป็นแถบเตือนต่อไป
3. ตรวจว่าบันทึกรายการได้ตามปกติหลังรับทราบ

## 3. อุปกรณ์ใช้ร่วมกัน (A ค้างคิว, B ล็อกอินต่อ)
1. A บันทึกรายการออฟไลน์ แล้วออกจากระบบ
2. B ล็อกอินบนเครื่องเดียวกัน เลือกรับช่วงคิวด้วยรหัสผ่านของ B
3. ซิงก์ ตรวจว่าผู้บันทึกคือ A และผู้ดำเนินการในบันทึกตรวจสอบคือ B
4. ลองใส่รหัสผ่านผิด ตรวจว่าไม่รับช่วง

## 4. ความขัดแย้งและรายการเก่า
- [ ] สองเครื่องจ่ายอุปกรณ์เดียวกันออฟไลน์ แล้วซิงก์: สำเร็จหนึ่ง ขัดแย้งหนึ่ง ผู้ตรวจสอบปิดรายการที่หน้าตรวจสอบได้
- [ ] รายการย้อนหลังเกิน 7 วัน ถูกแยกไว้ให้ตรวจ และกด "ใช้ตอนนี้" ได้ตามสิทธิ์

## 5. การสำรองข้อมูลไป Google Drive และกู้คืน
1. รันงานสำรองข้อมูลตาม `docs/runbooks/PR24_BACKUP_RESTORE_RUNBOOK.md` ตรวจว่าไฟล์ขึ้น Drive
2. ดาวน์โหลดไฟล์สำรองจาก Drive มาที่เครื่องทดสอบ (ไม่ใช่เครื่องใช้งานจริง)
3. กู้คืนตามคู่มือ แล้วตรวจจำนวนอุปกรณ์/ธุรกรรมและเข้าสู่ระบบได้
4. จดเวลาที่ใช้ และปัญหาที่พบ

## 6. อัปเดตแอปขณะมีรายการค้างในคิว
1. สร้างรายการออฟไลน์ค้างไว้ 1-2 รายการ (อย่าซิงก์)
2. ติดตั้งแอปเวอร์ชันใหม่บนเครื่องของหน่วยงาน
3. เปิดแอปบนอุปกรณ์ ตรวจว่ามีข้อความให้อัปเดต คิวไม่หาย และไม่รีโหลดเองขณะกำลังบันทึก
4. อัปเดตแล้วซิงก์ ตรวจว่ารายการค้างถูกส่งครบ
5. กรณีเวอร์ชันเก่าเกินไป (CLIENT_TOO_OLD): คิวต้องยังอยู่ และมีข้อความให้อัปเดต
