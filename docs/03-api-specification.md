# API Specification

> **Status: Legacy design reference.** Some proposals and scale targets in
> this document predate confirmed guardrails and may be superseded. Use
> `AGENTS.md`, `PROJECT_PLAYBOOK.md`, `ARCHITECTURE_DECISIONS.md`, and the
> consolidated implementation plan for current authority.

Base URL: `/api/v1`. Full interactive spec auto-generated by FastAPI at **`/api/docs`** (Swagger UI) and **`/api/redoc`**; raw OpenAPI JSON at **`/api/openapi.json`**. This document summarizes the contract; the running Swagger UI is the source of truth.

## Conventions

- **Auth**: `Authorization: Bearer <access_token>` (JWT). Login issues access token (15 min) + refresh token (httpOnly cookie, 7 days).
- **Pagination**: cursor-based, `?limit=25&cursor=<opaque>` → response `{ items: [...], next_cursor: "..." | null, total: number }`. Offset pagination (`?page=&page_size=`) also supported for simple admin tables.
- **Filtering**: `?status=available&department_id=...&category_id=...`
- **Sorting**: `?sort_by=updated_at&order=desc`
- **Search**: `?q=<text>` full-text/fuzzy across asset_number, serial_number, equipment_name, qr_code_value
- **Errors**: RFC7807-style `{ "detail": "...", "code": "EQUIPMENT_NOT_AVAILABLE", "status": 409 }`
- **Idempotency**: mutating POSTs accept optional `Idempotency-Key` header (for offline-sync retries)

## Endpoints

### Auth
| Method | Path | Description | Role |
|---|---|---|---|
| POST | `/auth/login` | employee_code/email + password → access+refresh token | Public |
| POST | `/auth/refresh` | refresh token → new access token | Public (valid refresh cookie) |
| POST | `/auth/logout` | revoke refresh token | Authenticated |
| GET | `/auth/me` | current user profile + permissions | Authenticated |

### Equipment
| Method | Path | Description | Role |
|---|---|---|---|
| GET | `/equipment` | list/search/filter/paginate | All |
| GET | `/equipment/{id}` | detail + status history + upcoming PM/CAL | All |
| GET | `/equipment/by-qr/{qr_value}` | resolve QR scan → equipment detail (used by Borrow/Return flow) | All |
| POST | `/equipment` | create | Admin, Biomedical Engineer |
| PATCH | `/equipment/{id}` | update fields | Admin, Biomedical Engineer |
| DELETE | `/equipment/{id}` | soft delete | Admin |
| GET | `/equipment/{id}/qrcode` | generate/return QR PNG/SVG for printing | Admin, Biomedical Engineer |
| POST | `/equipment/{id}/status` | manual status change (PM/CAL/Repair/Out of Service/Lost) + reason | Admin, Biomedical Engineer |
| GET | `/equipment/{id}/history` | full status + borrow history timeline | All |

### Borrow / Return
| Method | Path | Description | Role |
|---|---|---|---|
| POST | `/borrow` | create borrow transaction (validates Available, atomically flips status) | Ward Nurse, Transport Staff, Admin |
| GET | `/borrow/active` | list currently-borrowed items (for overdue tracking) | All |
| POST | `/return/{transaction_id}` | complete return: condition, next status, photo, signature | Ward Nurse, Transport Staff, Admin, Biomedical Engineer |
| GET | `/transactions` | paginated transaction history with filters (ward/date range/equipment) | All |
| GET | `/transactions/{id}` | transaction detail | All |

### Dashboard
| Method | Path | Description |
|---|---|---|
| GET | `/dashboard/summary` | counts by status, PM/CAL due-soon counts (Redis-cached 15s) |
| GET | `/dashboard/borrow-trend?range=30d` | time series for chart |
| GET | `/dashboard/top-borrowed?limit=10` | most-borrowed equipment |
| GET | `/dashboard/stream` | Server-Sent Events, live push on status change |

### Reports
| Method | Path | Description |
|---|---|---|
| GET | `/reports/export?format=xlsx\|csv\|pdf&type=borrow_frequency\|utilization\|downtime\|repair_cost` | generate + stream file |

### Users / Admin
| Method | Path | Description | Role |
|---|---|---|---|
| GET/POST/PATCH/DELETE | `/users` | user management | Admin |
| GET/POST/PATCH/DELETE | `/departments`, `/wards`, `/locations`, `/categories` | master data | Admin |
| GET | `/audit-logs` | filterable audit trail | Admin |

### Notifications
| Method | Path | Description |
|---|---|---|
| GET | `/notifications` | current user's notifications |
| POST | `/notifications/{id}/read` | mark read |
| WS | `/ws/notifications` | live push |

## Example — Borrow

```http
POST /api/v1/borrow
Authorization: Bearer <token>
Content-Type: application/json

{
  "equipment_qr": "MEP:AST-00123",
  "borrower_name": "พยาบาล สมหญิง",
  "ward_id": "…uuid…",
  "phone_number": "0891234567",
  "pickup_location_id": "…uuid…",
  "dropoff_location_id": "…uuid…",
  "quantity": 1,
  "notes": ""
}
```

Response `201`:
```json
{
  "id": "…uuid…",
  "transaction_no": "TX-20260716-0001",
  "equipment": { "id": "…", "asset_number": "AST-00123", "status": "borrowed" },
  "borrowed_at": "2026-07-16T09:12:00+07:00"
}
```

Response `409` if equipment not Available:
```json
{ "detail": "Equipment is currently in status 'repair'", "code": "EQUIPMENT_NOT_AVAILABLE", "status": 409 }
```
